# 19. Uninstall from the panel and Windows' uninstaller (2026-11-24)

The owner's request after M16, planned and built as M17. Decisions D-951 on, risks R-441 on (the
documentation task numbers them).

## 1. The owner's words

```
make sure windows installer does also creates a uninstaller. we need full uninstall inside the
maintenence of the panel
```

## 2. Questions and answers

- Q-82: what the panel's uninstall offers. Answer: both "Keep the data" and "Remove everything", as
  the command line.
- Q-83: a backup before "Remove everything". Answer: offered, not required.
- Q-84: how hard to press by accident. Answer: "Confirm it's you", then typing "uninstall" unlocks
  the button.
- Q-85: whether Claude may uninstall. Answer: no, never: the route is hidden from Claude.
- Not asked (the lead's default): Windows' uninstaller is xDesign's entry in Windows' list of
  installed apps (Settings > Apps > Installed apps, and Control Panel > Programs and Features),
  whose Uninstall button runs `xdesign --uninstall`; no Start menu entry.

## 3. Windows' list of installed apps (UNINST-01)

- The installer writes the key `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\xDesign`
  in its step "Installed apps" (step 11 of 14, right after "Start and health check"):
  `DisplayName` "xDesign", `DisplayVersion` the release's version, `Publisher` "xDesign",
  `DisplayIcon` `"C:\Program Files\xDesign\current\xdesign.exe",0`, `InstallLocation`
  `C:\Program Files\xDesign`, `InstallDate` (yyyymmdd), `EstimatedSize` (the program folder in KB),
  `NoModify` 1, `NoRepair` 1, `UninstallString`
  `"C:\Program Files\xDesign\current\xdesign.exe" --uninstall`. `install.json` records it as
  `apps_entry`.
- An update and a rollback set `DisplayVersion` and `EstimatedSize` again (and write the whole key
  when it is missing); `--uninstall` removes the key in its last step, so the list's Uninstall
  button works while anything is left to remove; a repair writes it again.
- Started from that list (or from Explorer) without Administrator, `xdesign.exe --uninstall` starts
  itself again with the Administrator prompt, as the double-clicked installer does (WIN-04b); in a
  terminal it refuses without Administrator as before. The elevated window waits at the end with
  "Press Enter to close this window."; refused, it says "Run this in a terminal opened as
  Administrator." and waits for Enter.

## 4. Maintenance > "Uninstall xDesign" (UNINST-02)

The last card of Maintenance, for the site owner, on Linux and Windows servers (never in the
desktop app). Its texts:

- Title "Uninstall xDesign"; description "Removes xDesign from this server. The site stops at once."
- Two choices (a radio group), none chosen at first:
  - "Keep the data": "The program goes. The designs, the settings and the backups stay on this
    server; installing xDesign again picks them up."
  - "Remove everything": "The program, the designs, the settings and the backups on this server go.
    This cannot be undone."
- The backup offer: "Make a backup and download it before you uninstall. With Remove everything,
  the backups on this server go too." and the button "Download a backup" (makes a new backup and
  downloads it, "Making a backup..." meanwhile; then "Downloaded <file name>."). Not required.
- The field "Type uninstall to confirm" (placeholder "uninstall"); the button "Uninstall xDesign"
  (destructive) works once a choice is made and the field holds "uninstall" (spaces around it and
  letter case ignored), then "Confirm it's you" as for the other dangerous actions.
- After the request: the card shows "Uninstalling xDesign..." with the lines "Waiting for the
  server to take the request." and then "The uninstaller started. The site stops in a moment.";
  the page then asks `GET /api/health` every 2 seconds and, after 3 failures in a row, shows
  "xDesign is uninstalled from this server." with "Its data stays on the server: installing
  xDesign again picks it up." (Keep the data) or "Nothing of it is left on the server." (Remove
  everything). If the site still answers 3 minutes after the uninstaller started: "xDesign still
  answers: the uninstall did not finish. Run xdesign --uninstall on the server." A request the
  helper refuses or that fails shows the helper's words, as the other maintenance requests do.
- Activity: "Started the uninstall: keep the data" or "Started the uninstall: remove everything".
- The route `POST /api/maintenance/uninstall` (body `keepData`, site owner, "Confirm it's you",
  answering the maintenance request) is hidden from Claude (Q-85) and refused in the desktop app.

## 5. The helper's run (UNINST-01)

- The control server's `POST /maintenance/uninstall` with `{"keepData": true|false}` writes the
  maintenance request of kind `uninstall` and starts the maintenance helper (the path unit on Linux,
  the service `xdesign-maintenance` on Windows); it answers the request as the other kinds do.
- The maintenance helper checks the request, shows the step "Starting the uninstaller", records the
  request as done ("The uninstaller started.") and then starts the uninstaller detached from
  itself: `xdesign --uninstall --yes` with `--keep-data` or `--remove-everything`, `--no-backup`
  (the panel offered the backup) and, with Remove everything on Linux, `--undo-selinux`. One that
  does not start writes the result again: "The uninstaller did not start: <why>. Nothing was
  changed."
  - On Linux it is the transient unit `xdesign-uninstall-<time>.service` (`systemd-run --collect`),
    so stopping and removing the maintenance units does not end it, and it runs the release's own
    file `/opt/xdesign/releases/<version>/xdesign`, not a copy in `/var/tmp`: the maintenance
    service has `PrivateTmp`, which hides its `/var/tmp` from the transient unit, and SELinux keeps
    systemd from starting a file labeled `tmp_t`; Linux lets the running uninstall delete its own
    file.
  - On Windows the maintenance service copies `xdesign.exe` into a new folder
    `C:\Windows\Temp\xdesign-uninstall-<time>\` (permissions for SYSTEM and Administrators only,
    never an existing one) and starts the copy outside the service's job, so deleting the
    services does not end it. The uninstall has Windows delete the folder at the next restart, as
    WIN-04b's uninstaller does.
- `serve` refuses the request (409) while a backup runs, as `set-port` does.
- The uninstall's log is the command line's (`/var/log/xdesign-install.log` on Linux,
  `C:\ProgramData\xDesign\logs\install.log` on Windows, kept by Remove everything as WIN-04b
  decided).

## As built (M17)

**UNINST-01** (c1a96a6), the helper. Section 3: the installer's step "Installed apps" (step 11 of
14 on Windows, right after "Start and health check", under "Finishing...") writes the key with the
values above; InstallDate is the local date, and a key that has one keeps it. A repair compares
every value with what it would write and writes the key again where one differs. EstimatedSize is
the size of the files under C:\Program Files\xDesign in KB, rounded up, without following the
current junction. install.json records it as "apps_entry":
"HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\xDesign". An update and a rollback set
DisplayVersion and EstimatedSize at the end of their Finish step (an update once the old releases
are removed); a key that is missing is written whole there, and a failure is only a warning.
`--uninstall` deletes the key in its last step, "Installed apps", after "Remove the program", so
the list's Uninstall button works while anything is left to remove. Started in a window of its own
(GetConsoleProcessList counts this process alone: the list's Uninstall button, or Explorer) without
Administrator, `xdesign.exe --uninstall` starts itself again with its arguments through the
Administrator prompt (ShellExecute with "runas"); the elevated window asks the uninstall's
questions and ends with "Press Enter to close this window."; a refused or cancelled prompt says
"Run this in a terminal opened as Administrator." and waits for Enter. In a terminal nothing
changed: without Administrator it refuses as before. Section 5: `POST /maintenance/uninstall` takes
exactly `{"keepData": true}` or `{"keepData": false}`; a missing or null keepData answers 400
"Choose Keep the data or Remove everything.", another type or another field 400 as the other
routes. serve refuses (409) while a backup runs ("A backup is running. Try again when it ends."),
as set-port does, and answers 202 with the request, whose part is `"uninstall": {"keep_data":
...}`. The maintenance helper shows the step "Starting the uninstaller", writes the result "The
uninstaller started." and only then starts the uninstaller: `xdesign --uninstall --yes --keep-data
--no-backup`, or `--remove-everything --no-backup` with `--undo-selinux` on Linux. One that does
not start writes the result again: "The uninstaller did not start: <why>. Nothing was changed." On
Linux the uninstaller is the transient unit xdesign-uninstall-<UTC time, yyyymmddThhmmssZ>.service
(`systemd-run --quiet --collect --service-type=exec`, so a file systemd cannot start is an error
in the result), and it runs the release's own file /opt/xdesign/releases/<version>/xdesign instead
of a copy in /var/tmp: xdesign-maintenance.service has PrivateTmp=yes, so its /var/tmp is one the
transient unit does not see and systemd deletes when the unit stops, and SELinux keeps systemd
from starting a file labeled tmp_t; Linux lets the running uninstall delete its own file, as `sudo
xdesign --uninstall` from the PATH does. Its lines are in `journalctl -u
xdesign-uninstall-<time>`. On Windows the maintenance service copies xdesign.exe into
C:\Windows\Temp\xdesign-uninstall-<UTC time>\, a new folder made with permissions for SYSTEM and
Administrators only (one that exists is never used), and starts the copy with DETACHED_PROCESS,
CREATE_NEW_PROCESS_GROUP and CREATE_BREAKAWAY_FROM_JOB (without the last when a job allows no
breakaway), the copy's folder as its current folder and NUL as its standard streams. At its end
that uninstall has Windows delete the folder at the next restart (MoveFileEx) and lists it under
"What remains". The step "Starting the uninstaller" and the result's words are what GET
/maintenance shows: the progress has step "uninstall", the result kind "uninstall", ok true.

**UNINST-02** (15a7165), the API, the server and the website. The route `uninstall` (`POST
/api/maintenance/uninstall`, body `{ keepData: boolean }`, answer `maintenanceRequest`, site owner)

choice cards of Settings > HTTPS's methods (a radio button with an icon, its name and words):
"Keep the data" with a database icon, "Remove everything" with a bin icon. "Download a backup"
makes the backup as "Make a backup now" does (no "Confirm it's you"), then downloads it as
Backups' "Download" does: "Confirm it's you" unless this tab confirmed in the last 5 minutes. The
line under the button says "Making a backup..." meanwhile and "Downloaded <file name>." once the
browser has the file; a failed backup shows the helper's words as a toast, as Backups does. The new
backup shows in Backups at once. "Uninstall xDesign" asks "Confirm it's you" every time (the window
of the last 5 minutes does not count): the dialog's title "Uninstalling xDesign", its words the
chosen choice's description and "It needs your password." (or "your password and a code"), its
button "Uninstall xDesign"; a refused request shows the helper's words in the dialog. While the

Maintenance busy (their buttons off) until it ends with "Done"; the site stopping follows its
result. The health poll waits 2 seconds after each answer, not on a fixed clock. Claude's

`MethodCard` of `HttpsIssueDialog.tsx` is exported for the two choices. Activity shows "Started
the uninstall: keep the data" or "Started the uninstall: remove everything".
